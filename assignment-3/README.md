I created four tables: artists, songs, playlists and playlist\_songs, to organize the data and avoid repeating information. Each table uses a primary key to identify its records, while foreign keys connect songs to artists and playlists to songs. The playlist\_songs table handles the many-to-many relationship between songs and playlists, and its composite primary key prevents the same song from being added twice to one playlist. I used a UNIQUE constraint to ensure that two songs cannot have the same position in a playlist, and stored song durations as integers representing seconds. I chose not to store the total duration or number of songs in a playlist because these values can be calculated using SQL queries.
